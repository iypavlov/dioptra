# Screen OCR Translator — План реализации

## 1. О проекте

Desktop-программа для Windows, которая распознаёт **отдельное английское слово** на экране под курсором мыши по нажатию хоткея и показывает его перевод в модальном окне. Проект закладывается как база для последующего расширения: подключения LLM для перевода, TTS-озвучки, click-through оверлея и прочего.

**Краткий флоу:**
1. Пользователь запускает программу → она сворачивается в трей
2. Наводит курсор на **незнакомое слово** в игре/приложении
3. Нажимает `Ctrl+Shift+T` (или другой хоткей)
4. Программа: определяет позицию курсора → захватывает небольшую область вокруг → распознаёт все слова в ней (PaddleOCR с боксами) → находит слово, на которое указывает курсор → переводит **только это слово** → показывает результат в модальном окне рядом с курсором

## 2. Анализ существующих проектов

Перед началом разработки был проведён анализ open-source аналогов. Ниже — ключевые находки:

| Проект | Стек | Подход | Сильные стороны | Слабые стороны |
|--------|------|--------|----------------|----------------|
| **Translation-Overlay** | Electron + TypeScript | Выделение области → PaddleOCR/Tesseract → перевод в оверлей | Офлайн-перевод (Bergamot), умный Lock Mode, кроссплатформа | Тяжёлый (Electron), нет захвата под курсором |
| **ocr_trans** | Rust + Slint | VLM (Gemini/OpenAI) для захвата + перевода в одной модели | Мгновенный старт, красивый UI, Click-Through | Rust не самый быстрый для прототипа |
| **OCR-Translator** | Python + PySide6 | Область → PaddleOCR/EasyOCR → Google/DeepL/Ollama | Много движков, активная разработка | Только выделение области, сложная настройка |
| **BoxTrans** | Python + CustomTkinter | PaddleOCR (GPU) + DeepL | Быстрый OCR, готовый билд 1GB | Проприетарный, нет захвата под курсором |
| **SnapTraTranslator** | Swift (macOS) | Hover + OCR → всплывающая подсказка | Единственный делает hover-захват | Только macOS |
| **K-Lite** | C# .NET WPF | Windows.Media.Ocr, минимализм | 0 зависимостей, сверхлёгкий | Только копирует текст, нет перевода |
| **ScreenFind** | .NET WPF | Windows.Media.Ocr, поиск по экрану | Поиск текста + fuzzy matching | Не переводчик |

**Ключевые выводы:**
- Большинство проектов используют **выделение области** (drag to select), а не захват под курсором
- Только SnapTraTranslator (macOS) реализует hover-подход — он и есть ближайший аналог
- **PaddleOCR** стабильно показывает лучшую точность на игровом/экранном тексте (85-90%) по сравнению с Tesseract (60-70%)
- В 2026 году также становятся популярны VLM-подходы (Gemini Vision, Qwen-VL) — единая модель вместо OCR + перевод

## 3. Обоснование выбора стека

### Язык: Python 3.11+

| Критерий | Оценка |
|----------|--------|
| Скорость прототипа | ⭐⭐⭐⭐⭐ — богатая экосистема, минимум бойлерплейта |
| OCR-экосистема | ⭐⭐⭐⭐⭐ — PaddleOCR, EasyOCR, Tesseract — всё на Python |
| GUI для оверлея | ⭐⭐⭐⭐ — PyQt6/PySide6 — зрелые, frameless-окна, DPI-aware |
| Производительность | ⭐⭐⭐ — GIL, но OCR и перевод — I/O-bound задачи |
| Сборка .exe | ⭐⭐⭐⭐ — PyInstaller / Nuitka давно стабильны |
| Сообщество | ⭐⭐⭐⭐⭐ — максимум решений любой проблемы |

**Альтернативы:**
- **C# .NET** — встроенный Windows.Media.Ocr, нативная WinRT, выше производительность, но медленнее разработка
- **Rust** — максимальная скорость, минимальный размер .exe, но долго и сложно для прототипа
- **C++ + Qt** — производительно, но слишком много кода для MVP

### OCR: PaddleOCR

PaddleOCR (PP-OCRv4/v5) — лучший открытый OCR-движок для задачи в 2026 году:

| Характеристика | PaddleOCR | Tesseract | EasyOCR | Windows.Media.Ocr |
|---------------|-----------|-----------|---------|-------------------|
| Точность (game text) | 85-90% | 60-70% | 80-85% | 75-85% |
| Скорость (GPU) | 12.7 fps | — | 4.2 fps | — |
| Скорость (CPU) | ~0.5-2s | ~0.1-0.5s | ~0.8-3s | ~0.1-0.3s |
| Языки | 80+ | 100+ | 80+ | 25+ |
| GPU ускорение | ✅ (CUDA) | ❌ | ✅ | ❌ |
| Сложность установки | Средняя (PaddlePaddle) | Низкая | Низкая | Нулевая (вшита в ОС) |
| Размер | ~500 MB | ~40 MB | ~500 MB | 0 MB |

**PaddleOCR выигрывает** на игровых шрифтах, тексте на сложном фоне и при наличии GPU.

### GUI: PyQt6

- Нативная поддержка прозрачных frameless-окон (`setWindowFlags(Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint)`)
- Аппаратное ускорение через QGraphicsView
- DPI-aware из коробки (HighDPI Scaling)
- Зрелое API, огромное комьюнити
- Лицензия GPL/LGPL — не проблема для open-source проекта

### Перевод: Google Translate с абстракцией под LLM

На старте — **Google Translate** (бесплатно, без API-ключа через `deep-translator`). Архитектура через абстрактный класс `AbstractTranslator` позволит в будущем:

- Подключить DeepL (платно, но качественнее)
- Подключить Ollama с локальной LLM (полная приватность)
- Подключить Gemini/OpenAI API (контекстный перевод, умный пересказ)

### Хоткей: `keyboard`

Библиотека `keyboard` — единственный простой способ повесить **глобальный** хоткей в Python на Windows. Работает через SetWindowsHookEx. Альтернативы: `pynput` (сложнее), `win32api` (низкоуровнево).

### Ключевые архитектурные решения

**1. Абстрактный переводчик (`AbstractTranslator`)**

```python
class AbstractTranslator(ABC):
    @abstractmethod
    def translate(self, text: str, source: str = "en", target: str = "ru") -> str:
        ...
```

Любой новый движок просто наследует этот класс. Фабрика или конфиг решает, какой использовать:

```python
class TranslatorFactory:
    _registry: dict[str, type[AbstractTranslator]] = {}

    @classmethod
    def register(cls, name: str, translator_cls: type[AbstractTranslator]):
        cls._registry[name] = translator_cls

    @classmethod
    def create(cls, name: str, **kwargs) -> AbstractTranslator:
        return cls._registry[name](**kwargs)
```

**2. Поиск слова под курсором (WordFinder)**

Это ключевое отличие от аналогов — мы переводим **одно слово**, а не всё подряд. Алгоритм:

1. Захватываем область **~200×60 px** вокруг курсора (достаточно для одного слова с запасом)
2. PaddleOCR возвращает список всех распознанных слов с их bounding box'ами:
   ```python
   [
     {"text": "inventory", "box": [[x1,y1],[x2,y1],[x2,y2],[x1,y2]], "confidence": 0.97},
     {"text": "capacity",  "box": [[x3,y3],[x4,y3],[x4,y4],[x3,y4]], "confidence": 0.95},
   ]
   ```
3. **WordFinder** получает список слов + позицию курсора относительно захваченного региона
4. Проверяет: какой bounding box содержит координату курсора (`box[0][0] ≤ cx ≤ box[1][0] and box[0][1] ≤ cy ≤ box[2][1]`)
5. Если курсор находится между словами — выбирается ближайшее слово по расстоянию до центра бокса
6. Переводится **только это слово**, а не вся строка

Это даёт:
- Минимальный размер захвата → быстрее OCR
- Переводится именно то слово, которое интересует пользователя
- Не нужно постинга (merging) строк

**3. Кэш переводов (SQLite)**

```sql
CREATE TABLE cache (
    screenshot_hash TEXT PRIMARY KEY,
    raw_word TEXT,
    translated_word TEXT,
    source_lang TEXT,
    target_lang TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

- Ключ — md5 от захваченного региона (бинарный, 16 байт)
- Если пользователь повторно навёл на то же слово и нажал хоткей — перевод из кэша (0 мс)
- TTL кэша — 1 час, потом устаревшие записи удаляются
- **Важно:** кэшируется перевод слова, а не региона. Если в регионе другое слово — кэш не сработает из-за другого хеша

**4. Модальное окно (PyQt6)**

- `Qt.FramelessWindowHint` — без рамок
- `Qt.WindowStaysOnTopHint` — поверх всех окон
- `Qt.WindowTransparentForInput` — клики проходят сквозь (опционально)
- `setAttribute(Qt.WA_TranslucentBackground)` — прозрачный фон
- Позиционирование: центр окна = позиция курсора + небольшой offset
- Авто-закрытие: по `ESC` или по клику вне окна

## 6. План поэтапной реализации

### Этап 1: MVP — базовый функционал

**Цель:** программа работает в трее, по хоткею показывает перевод текста под курсором.

| Шаг | Задача | Детали | Критерий готовности |
|-----|--------|--------|---------------------|
| 1.1 | `main.py` + трей-иконка | `pystray` с меню: Показать/Скрыть, Настройки, Выход. Иконка в `assets/`. | Программа запускается, висит в трее |
| 1.2 | `HotkeyManager` | Глобальный хоткей `Ctrl+Shift+T`. Импорт `keyboard.add_hotkey()`. Требуются права администратора. | Нажатие хоткея вызывает callback |
| 1.3 | `ScreenshotService` | Получить курсор (`pyautogui.position()`), захватить регион ~200×60 px вокруг него (`mss.grab()`) | На выходе — `PIL.Image` + координаты региона |
| 1.4 | `OcrService` | PaddleOCR → список `[(text, box, confidence), ...]` на уровне слов (использовать `det_db_box_thresh`) | Возвращаются боксы каждого слова |
| 1.5 | `WordFinder` | Сопоставить позицию курсора (отн. региона) с боксами → найти слово. Проверка: `point_in_box(cursor, box)`. Fallback: расстояние до центра бокса. | Возвращается одно слово (строка) |
| 1.6 | `AbstractTranslator` + `GoogleTranslate` | Интерфейс + реализация на `deep-translator`. Фабрика для регистрации. | `factory.create("google").translate("Hello")` → "Привет" |
| 1.7 | `ModalOverlay` | PyQt6 frameless-окно: только перевод слова, кнопка закрыть, ESC для закрытия. Появляется рядом с курсором. | При вызове `show(text, pos)` — окно отображается |
| 1.8 | Интеграция в `main.py` | Связать всё: хоткей → скриншот → OCR → WordFinder → перевод → модалка | Полный цикл работает |
| 1.9 | `TranslationCache` | SQLite-кэш: ключ = md5(скриншота); перед OCR проверяем; если есть — используем | Повторный захват — моментальный |

**Длительность:** ~3-5 дней
**Результат:** .exe-файл, который делает то, что нужно

### Этап 2: Улучшение качества

| Задача | Описание |
|--------|----------|
| Адаптивный размер захвата | Если в регионе не найден текст — расширяем область |

### Этап 3: Расширение

| Задача | Описание |
|--------|----------|

## 9. Риски и их митигация

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| PaddleOCR долго грузится (>3с) | Высокая | Среднее | Инициализация при старте, а не по хоткею. Show loading-индикатор. |
| keyboard требует админ-права | Высокая | Низкое | Запуск от администратора, либо fallback на polling |
| Игра блокирует захват экрана | Средняя | Высокое | Использовать DXGI/DirectX capture (библиотека `dxcam`) |
| PaddleOCR ~500 MB в сборке | Средняя | Среднее | Использовать UPX-сжатие, или перейти на Windows.Media.Ocr |
| Google Translate заблокирован | Низкая | Среднее | Встроить поддержку прокси, fallback на Ollama |
| Низкая точность на мелком тексте | Средняя | Среднее | Image preprocessing перед OCR (upscale, threshold) |
| Одно слово не распознаётся изолированно | Средняя | Высокое | Взять контекст (2-3 слова слева/справа) и перевести только целевое слово через LLM в будущем |

## 10. Чему научиться в процессе

1. Работа с Win32 API через Python (hwnd, SetWindowsHookEx, Layered Windows)
2. PaddleOCR: детекция + распознавание, bounding box'ы, confidence scores
3. Глобальные хоткеи в Windows (low-level keyboard hook)
4. PyQt6: frameless-окна, оверлей поверх игр, события клавиатуры
5. Паттерн Strategy/Abstract Factory для подмены сервисов (переводчики)
6. PyInstaller / Nuitka — сборка Python-проектов в standalone .exe
